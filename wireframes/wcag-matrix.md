# WCAG 2.1 AA Mapping Matrix

Target standard: **WCAG 2.1 Level AA**. Components and implementation details refer to the three wireframe pages (`index.html`, `services.html`, `booking.html`) and `main.css`.

Contrast ratios in this document were computed with the WCAG relative-luminance formula, and are repeated in the `main.css` comments.

| # | Criterion ID & Name | Target Interface Component | Technical Implementation Detail | Verification Strategy |
|---|---|---|---|---|
| 1 | **1.3.1 Info and Relationships** (A) | Page structure, forms, result lists, appointment summary | Landmarks `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`. Each form control has a `<label for>`. Filter groups use `fieldset` with `legend`. Cards and results are `ul` / `li`. Appointment details use a `dl`. Hints and errors are tied to inputs with `aria-describedby`. | Run axe-core. In NVDA, list landmarks (`D`), headings (`H`) and form fields (`F`) and confirm the names and order. Disable CSS and check the page still reads in a logical order. |
| 2 | **1.4.1 Use of Color** (A) | Links, current nav item, required fields, errors | Body links are underlined. The current page uses bold plus a thick underline. Required fields say "(required)" in text. Errors show an icon plus the word "Error:" and a thicker border, never colour alone. | View the pages in greyscale (DevTools rendering emulation) and confirm every state is still distinguishable. |
| 3 | **1.4.3 Contrast (Minimum)** (AA) | All text on all backgrounds | Body text `#1b1c1c` on `#fbf9f9` is 16.28:1 and on `#ffffff` is 17.08:1. Muted text `#414751` on `#ffffff` is 9.35:1. Accent `#005796` on `#ffffff` is 7.49:1. White on `#005796` buttons is 7.49:1. Error `#ba1a1a` on `#ffffff` is 6.46:1. `#93000a` on `#ffdad6` is 7.24:1. | Re-check each pair in a contrast checker. Run Lighthouse and axe colour-contrast rules. Record any change to the palette here and in `main.css`. |
| 4 | **1.4.10 Reflow** (AA) | All layouts: card grid, filters, booking grid | Grids use `minmax` and `auto-fit`. Below 60rem the services, listing, location and booking layouts become one column. Sizes use `rem`. No fixed-width containers. | Set the browser to 400% zoom (equivalent to 320 CSS px) and confirm no horizontal scrolling and no clipped content. Test at 320px width in DevTools. |
| 5 | **1.4.11 Non-text Contrast** (AA) | Input borders, checkboxes, buttons, focus ring, error borders | Input and card borders `#717782` are 4.50:1 on `#ffffff`. Focus ring `#005796` is 7.14:1 on the page background. Error border `#ba1a1a` is 6.46:1 on `#ffffff`. The lighter `#c1c7d2` (1.62:1) is used only for decorative dividers. | Measure each border and indicator against its adjacent background. Confirm no input relies on the decorative colour. |
| 6 | **2.1.1 Keyboard** (A) | Navigation, search, filters, results links, booking form, pagination | Only native interactive elements are used (`a`, `button`, `input`, `details`/`summary`). No JavaScript and no `tabindex` greater than 0. Source order matches visual order. | Complete a full search, filter and booking flow using only the keyboard. Confirm every control is reachable and operable, and there are no traps. |
| 7 | **2.4.1 Bypass Blocks** (A) | Header and primary navigation on every page | A "Skip to main content" link is the first focusable element and targets `#main`. It is hidden off-screen until focused. | Press `Tab` once on each page and confirm the link appears and moves focus to the main content. |
| 8 | **2.4.2 Page Titled** (A) | Document `<title>` | Each page has a unique, descriptive title that starts with the page name, for example "Services \| Poopedi Healthcare Clinic". | Check each tab title. Confirm NVDA announces it on page load. |
| 9 | **2.4.4 Link Purpose (In Context)** (A) | Service cards, search results, pagination | Every link has a distinct accessible name, for example "Book Urgent Triage Slot" and "Book Chronic Disease Follow-up", instead of repeated "Book now" or "Read more". | Open the NVDA links list (`NVDA+F7`) and confirm no two unrelated links share a name. |
| 10 | **2.4.6 Headings and Labels** (AA) | Page headings, form labels, filter group names | One `h1` per page, no skipped levels, descriptive `h2` / `h3` headings. Labels state what to enter. | Review the headings outline with an extension or NVDA. Confirm the heading tree matches the page structure. |
| 11 | **2.4.7 Focus Visible** (AA) | Every link, button, input, summary | Global `:focus-visible { outline: 3px solid #005796; outline-offset: 2px; }`. The default outline is never removed without replacement. | Tab through each page and confirm a visible ring on every stop, against white, grey and blue backgrounds. |
| 12 | **3.1.1 Language of Page** (A) | `<html>` | `<html lang="en">` on every page. | axe-core check. Confirm NVDA reads with the correct voice. |
| 13 | **3.2.3 Consistent Navigation** (AA) | Primary navigation and footer | Identical header, nav links, order and footer on all three pages. Only the `aria-current="page"` link changes. | Compare the header and footer across the pages. Confirm order and labels are unchanged. |
| 14 | **3.3.1 Error Identification** (A) | Booking form | A static error summary lists each problem with a link to its field. Each invalid field has an inline message that begins "Error:", an icon, `aria-invalid="true"` and `aria-describedby` pointing to the message. | With NVDA, submit with invalid data. Confirm the summary is reached first, each link moves focus to the field, and the message is read with the field. |
| 15 | **3.3.2 Labels or Instructions** (A) | Booking and search forms | Visible labels on every field, hint text before each field, "(required)" or "(optional)" in text, and a note stating all fields are required unless marked optional. Correct `autocomplete` values on name, phone and email. | Check that every field is announced with a label, instruction and required state. Run axe label rules. |
| 16 | **4.1.2 Name, Role, Value** (A) | Filters, buttons, nav, checkboxes | Native elements expose role, name and state: `details`/`summary` for the disclosure state, `aria-current="page"` for the current page, `aria-invalid` for errors. No custom widgets without ARIA. | axe-core and the browser accessibility tree. Confirm each control reports a name, role and state in NVDA. |
| 17 | **4.1.3 Status Messages** (AA) | Results count on the listing page | `<p role="status">` is present in the page from load, with only its text changing, so assistive technology announces "Showing 12 results" without moving focus. | In NVDA, change a filter or search and confirm the new count is announced without focus moving. (Wireframes are static, so this is fully verified in the React build.) |

## Notes

- **Enhancements beyond AA:** buttons, links and form controls are at least 44 by 44 CSS px, which meets the stricter 2.5.5 Target Size (AAA) guidance. This project claims **AA**, and the larger targets are an additional usability measure.
- **Results status:** record the axe-core and Lighthouse results and the manual NVDA and keyboard findings in the README (Part C). This matrix lists the planned verification, not completed results.
- **React build:** criteria 14 and 17 (error handling and status messages) are only demonstrated statically in the wireframes. Their live behaviour is built and tested in Part B.
